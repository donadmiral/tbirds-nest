# Native app continuity inventory

Date: 2026-11-04. Scope: the actual native registry in `src/navigation/AppNavigator.tsx`, including conditional business/personal tabs, authentication branches, modal routes, duplicate aliases, and nested stacks.

## Coverage and meaning

- 98 registered `Screen` declarations were extracted from the TypeScript JSX AST.
- 92 declarations resolve to concrete screen files, covering 85 unique screen files.
- Six declarations are navigator wrappers. Repeated screen aliases and conditional registrations remain separate rows below.
- Source review checks initial loading, same-identity refresh, return navigation, data/error clearing, request lifetime, query/account isolation, and media authorization boundaries. It is not proof of rendered frame timing or physical-device coverage.
- `screen-refresh-continuity.cjs` executes production read callbacks with deferred responses. It covers transient failures, successful empties, denial, ordering, identity changes, blur and media-signing failure. The focused seven-file native regression run passed 142 tests, including the rendered Studio Inbox case. The final four-file follow-up passed 198 tests, including 50 continuity cases, the profile story deadline/cancellation case, Studio resources and actual Campaigns theme renders. Five added Community cases cover queued pagination and independent denial handling when a sibling request is malformed or rejects.
- The source audit and selected continuity corrections are complete. Every registration is accounted for below. Device-only latency and rendering checks remain explicitly separate.

## Verification boundary

No source audit can establish “faster than Twitter or Instagram,” zero dropped frames, or fully downloaded uncached media at cold launch. Those claims require identical devices, controlled network/cache states, and measured launch/refresh/interaction traces. This change set preserves usable content during authorized background work and verifies the state transitions described above.

Required device checks after building: cold authenticated launch, warm launch, tab return with scroll position, pull refresh with images visible, same-query retry, account switch, denied access, offline/error recovery, camera/call entry and dismissal, and slow-network interaction responsiveness.
