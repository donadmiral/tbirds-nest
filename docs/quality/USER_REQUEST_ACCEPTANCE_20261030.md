## Web feed scroll completion addendum

The earlier confirmed per-mode web scroll gap is now implemented in the working source. The actual scroll container is the document/window; posts stay in normal document flow, and no list virtualization or nested scroller was introduced. Each valid tab snapshot stores its offset alongside the existing rows/cursor/pagination state. Account changes and expired/invalid snapshots cannot restore another account or an obsolete offset. A fresh foreground refresh cancels any pending mode restoration.

A mode click saves the current position, then requests a single restore associated with that exact account, mode and request ID. The component starts it only for an explicit mode change; first mount and route return remain with the existing route scroll system. It checks both current controller state and rendered DOM identity, waits for the destination's ready content, and allows at most two seconds for sufficient height before clamping once. Loading cannot retain the request indefinitely. Rapid changes preserve an unapplied destination offset instead of saving the previous mode's temporary browser clamp.

Wheel, touch, pointer, keyboard, subsequent clicks, page hiding, history navigation, URL changes and other scroll movement cancel pending work. A genuine viewport clamp caused by shortened document height is distinguished from a separate intentional scroll. Stale callbacks cannot act on a later request, mode or account. Background updates and pagination do not repeatedly reposition the page.
